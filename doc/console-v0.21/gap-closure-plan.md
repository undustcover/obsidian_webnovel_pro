# 小说控制台 V0.21 缺失补齐与发布闭环方案

状态：待执行  
适用范围：`obsidian-webnovel-assistant-main` 小说控制台 V0.21 P0  
编制依据：`spec.md`、`plan.md`、`tasks.md`、`acceptance-matrix.md` 与 2026-09-10 真实 Obsidian 使用问题复盘

## 1. 结论与目标

V0.21 已具备领域模型、索引、查询、安全写入规划以及部分 Console UI，但尚未形成可发布的用户闭环。当前最直接的阻断是：当 `consoleProjects` 和旧 `workspaceFolders` 同时为空时，运行时没有项目上下文，Console 却把“尚未配置”统一显示为 `error`，也没有在界面内提供配置、重试或恢复入口。

此外，导航中多数页面只是落入同一通用搜索列表；若干已经存在的应用层操作没有可达的前端入口；Console 不订阅索引状态变化；源码、构建产物与候选安装目录还存在版本和内容漂移。原 P0-071、P0-072、P0-075 仍未完成，因此 V0.21 当前只能判定为“集成中”，不能判定为“已发布”。

本方案的目标是：

1. 新用户和旧用户打开 Console 后都能进入明确、可恢复的项目与索引状态。
2. P0 规范中的每项用户能力都有可达入口、正确页面语义和必要反馈。
3. 所有写操作都经过预览、影响展示和规定的确认边界。
4. 源码、版本、构建产物和 Obsidian 实际加载目录可追溯且一致。
5. 在真实 Obsidian 中完成 32 条验收并形成签字版发布结论。

## 2. 当前缺口基线

| 编号 | 缺口 | 用户影响 | 优先级 |
|---|---|---|---|
| G-01 | 空项目配置被映射为索引 `error` | 首次打开无法看到或操作小说 | 阻断 |
| G-02 | Console 内没有项目配置/选择/切换入口 | 用户无法从错误状态自助恢复 | 阻断 |
| G-03 | View 不订阅索引 state/snapshot | 早于索引完成打开时可能一直显示旧状态 | 阻断 |
| G-04 | UI 隐藏 `state.message`，没有重试/重建 | ERROR 无解释、无下一步 | 阻断 |
| G-05 | 多数导航路由共用无类型过滤的通用列表 | 页面名称存在，但职责和内容不成立 | P0 |
| G-06 | 当前阶段创建、游标推进、里程碑推进等应用能力无 UI 入口 | 后端存在但用户不可操作 | P0 |
| G-07 | 任务、建议、伏笔等部分仓储/命令未装配到 Console 操作流 | AC-18、AC-22、AC-23 缺少端到端证明 | P0 |
| G-08 | 异步 UI 操作缺少统一 loading/success/error 反馈 | 失败可能只进入开发者控制台 | P0 |
| G-09 | 自动测试把“无配置即 error”视为正确状态 | 测试全绿不能发现首次使用失败 | P0 |
| G-10 | 源码、manifest、构建包和候选插件目录不一致 | 可能加载旧代码或错误版本 | 阻断 |
| G-11 | P0-071、P0-072、P0-075 未完成 | 没有真实环境与最终发布证据 | 阻断 |

## 3. 范围与原则

### 3.1 本次必须补齐

- 项目首次配置、项目切换、索引生命周期、错误诊断与恢复。
- 所有 P0 导航页的确定性路由语义；没有独立复杂页面的功能至少必须有正确过滤、明确空态和可达详情。
- P0 规范已有的创建、编辑、推进、确认操作入口。
- 自动化回归、真实 Obsidian smoke、视觉/键盘验收、构建与发布一致性。

### 3.2 本次不扩展

- 不新增 `spec.md` 未定义的实体、字段、状态机或自动裁决能力。
- 不建设超出 P0 的完整可视化编辑器、AI 自动排期或移动端 Console。
- 不为追求 UI 完整而绕过 ChangePlan、ImpactReport、并发检查或确认令牌。
- 不把修复索引错误变成首次启用时批量改写 Markdown。

### 3.3 完成判定原则

一项能力只有同时满足以下条件才能标记完成：

1. 领域/应用实现存在且自动测试通过。
2. Console 中有用户可发现、可操作的入口。
3. loading、空态、成功、失败和恢复路径完整。
4. 写操作满足预览与确认要求。
5. 在实际构建产物和真实 Obsidian 中通过对应场景。

## 4. 补齐工作包

### Wave 7A：恢复发布基线与唯一运行事实

#### P0-076 冻结问题基线并校正验收状态

- 修改：`tasks.md`、`doc/console-v0.21/acceptance-matrix.md`
- 输出：将受真实使用问题影响的 AC 重新审计；记录“实现通过”和“端到端通过”的差异。
- 必查 AC：AC-01、AC-04、AC-06、AC-08、AC-12～16、AC-18、AC-22～25、AC-28、AC-30、AC-31。
- 验收：任何依赖用户入口的 AC，不得只凭 query/repository 单测保持“通过”。

#### P0-077 统一版本、构建与实际加载目录

- 修改：`package.json`、`manifest.json`、`versions.json`、构建/安装说明；必要时增加构建信息模块。
- 输出：明确“Console 功能版本 V0.21”与“插件发布版本”的关系；生成包含 commit、版本、构建时间的只读诊断信息。
- 验证：源码构建后的 `main.js`、`styles.css`、`manifest.json` 与测试 Vault 实际加载文件 hash 一致。
- 验收：Obsidian Console/设置页能查看版本与构建标识；候选发布目录中不存在旧 bundle 混用。

### Wave 7B：项目接入与索引生命周期闭环

#### P0-078 建立明确的 Console 可用性状态机

- 修改：`ConsoleIndexRuntime`、`ConsoleApplication`、索引状态类型。
- 状态至少区分：`unconfigured`、`initializing`、`ready`、`degraded`、`error`。
- 规则：没有项目配置是可操作的 `unconfigured`，不是技术错误；没有 snapshot 时禁止伪装成空数据成功。
- 错误对象：稳定错误码、用户消息、技术详情、项目 ID、可重试性和建议动作。
- 测试：空配置、非法配置、零文件项目、缓存损坏、扫描失败、部分文件失败。

#### P0-079 实现项目配置向导与项目切换器

- 新增 UI：首次打开引导页、项目根目录选择、目录映射预览、保存并初始化、取消返回。
- 工程要求：复用现有配置规范化逻辑；不得要求用户手写 JSON 才能使用基础功能。
- 多项目：工具栏显示当前项目，并允许切换；路由状态保存 `projectId`。
- 兼容：旧 `workspaceFolders` 可一键导入为显式项目映射；不得静默覆盖已有显式配置。
- 验收：全新 Vault、旧设置 Vault、显式多项目 Vault 均可仅通过 UI 进入 `ready`。

#### P0-080 支持运行时重配置和主动重建

- 修改：运行时提供受控的 `reconfigure/rebuild/retry`，无需重启插件才能应用合法项目映射。
- 生命周期：销毁旧监听/上下文，建立新上下文，保持原有 Markdown 不变。
- 缓存：提供“重建索引”动作；只清理目标项目派生缓存，不清理用户 Markdown。
- 验收：切换或修改项目后发布新 snapshot，旧项目事件不再污染当前项目。

#### P0-081 让 Console 响应索引状态与快照

- 修改：`NovelConsoleView` 在 `onOpen` 订阅 state/snapshot，在 `onClose` 解除订阅。
- UI：显示扫描进度、ready 记录数、degraded 文件数与详细错误；提供重试、重建、打开设置等上下文动作。
- 防抖：批量索引进度更新不得导致高频全页重排。
- 验收：索引前打开、索引中打开、索引后打开三种时序最终都自动进入正确状态。

### Wave 8A：路由与只读页面语义闭环

#### P0-082 建立声明式页面注册表

- 将每条 `ConsolePage` 映射到标题、实体类型、查询过滤、renderer、允许动作和空态。
- 删除“未知业务页自动回落到全实体列表”的隐式行为。
- 增加穷尽性测试：每一导航路由必须有页面定义且过滤语义正确。
- 验收：点击人物只显示人物，点击道具只显示道具，总控页面不再显示无关全实体列表。

#### P0-083 补齐总控页面

- `视图管理`：展示各入口、当前项目与数据计数。
- `当前阶段`：读取、创建和编辑 ProjectState，并走预览确认。
- `当前任务`：显示 now/missed/upcoming/later/needs_confirmation，支持打开来源和允许的状态操作。
- `小说总览`：展示结构、焦点、游标、健康摘要。
- `重要变更`：查询审计记录和影响摘要。
- `ID 注册表`：按类型显示占用、重复、缺失和候选 ID，只读诊断优先。
- `模板`：展示 P0 支持的模板和创建入口；不实现未定义的模板设计器。

#### P0-084 补齐叙事、设定与素材页

- 叙事路由按 BOOK/PART/VOL/UNIT/PLN/CH 精确过滤，并保留稀疏树导航。
- 设定路由按 WRL/CHR/ORG/LOC/ITM/ABL/TERM 精确过滤。
- 人物和道具详情必须展示现有 Query 已提供的经历、关系与冲突，不只显示计数。
- 素材路由按参考资料/灵感类型过滤；若 P0 仅承诺只读，界面必须明确标识。
- 验收：每个路由都有代表性 fixture、正确空态、原文入口和键盘可达详情。

### Wave 8B：写入与推进操作闭环

#### P0-085 补齐当前阶段、焦点与游标操作

- 接入 `previewProjectState`、`previewCursorProgression`。
- 支持首次创建当前阶段文件、设置唯一当前焦点、按故事线选择并推进游标。
- 所有推进先显示影响报告；取消不得写入。
- 验收：创建后 Dashboard 自动更新，重新加载仍能恢复，非法多焦点被阻断。

#### P0-086 补齐事件与里程碑操作

- 事件详情保留三状态和多视图重要度操作，并补齐创建/允许字段编辑入口。
- 里程碑详情接入条件结果展示和 `previewMilestoneProgression`。
- 跨线或不可比较时间必须保持现有领域规则，不由 UI 猜测。
- 验收：事件、游标、里程碑三类推进均能从页面到 ChangePreview、Transaction、索引刷新完整走通。

#### P0-087 补齐任务、建议与伏笔操作

- 将 CreativeTaskRepository、SuggestionService/Commands、ForeshadowingCommandService 装配进 ConsoleApplication。
- 任务：创建关联 EVT/MLS 的 TSK、允许的状态更新、来源/原因/锚点展示。
- 建议：接受、延后、忽略、不适用、转任务；只有转任务产生正式 TSK。
- 伏笔：展示埋设/推进/揭示锚点和错过提示；legacy 数据不自动升级。
- 验收：AC-18、AC-22、AC-23 必须增加真实 UI 操作证据。

#### P0-088 统一异步操作与错误反馈

- 新增统一 action runner：防重复提交、loading、成功 Notice、可理解错误、必要的技术详情。
- 所有 Promise 事件处理器必须捕获失败，不允许只产生 unhandled rejection。
- 执行成功后等待目标 snapshot，再刷新当前页面和详情。
- 验收：规划失败、确认过期、并发冲突、写入失败、索引刷新失败都有可恢复反馈。

### Wave 9：测试、真实环境和发布闸门

#### P0-089 增加首次使用与恢复集成测试

- 场景：空配置、旧 workspace 导入、非法 JSON/非法映射、多项目切换、零 Markdown、缓存损坏、扫描异常、Console 早于索引打开。
- 关键断言：空配置显示向导而非 ERROR；状态变化会自动刷新；失败保留上一个有效 snapshot。

#### P0-090 增加路由与操作可达性测试

- 对全部导航项做穷尽性测试。
- 建立“应用层 P0 命令 → Console 入口 → 预览 → 执行/取消”的追踪表。
- 禁止仅测试按钮存在；必须断言传入的 command、目标实体、字段白名单和确认要求。

#### P0-091 执行新旧 Vault 真实 Obsidian smoke

- 测试 Vault A：全新、无任何插件数据。
- 测试 Vault B：现有旧格式小说与旧设置。
- 测试 Vault C：minimal 新格式。
- 测试 Vault D：mixed-legacy 与故障样本。
- 每个 Vault 记录 Obsidian 版本、插件版本/构建标识、操作系统、主题、缩放、Leaf 宽度、步骤、预期与实际。
- 验收：从安装插件到打开小说、检索、查看详情、完成一次安全修改，全程不使用开发者控制台或手改 `data.json`。

#### P0-092 完成视觉、键盘与窄 Leaf 验收

- 延续 P0-072：100/125/150% 缩放、默认主题及至少一个常用明/暗主题、wide/medium/narrow。
- 键盘覆盖导航、搜索、列表/详情、Modal、确认/取消和错误恢复。
- 状态不可只用颜色表达；减少动画设置生效。

#### P0-093 完成回归、构建与候选包验证

- 必跑：type-check、lint、完整 test、coverage、CSS audit、i18n audit、10k benchmark。
- 从干净 commit 构建候选包；记录三个发布文件的 hash。
- 把同一候选包安装到真实测试 Vault 后重跑 P0-091 核心 smoke。
- 验收：禁止用源码开发目录通过结果代替候选发布包结果。

#### P0-094 执行最终验收并签字

- 依赖：P0-076～093、原 P0-071～075。
- 更新 32 条 AC 的最终状态和精确证据链接。
- 输出：签字版验收报告、已知限制、回滚步骤、发布/不发布决定。
- 发布条件：阻断缺陷为 0；AC-01～32 全部“通过”或存在明确批准的范围变更。

## 5. 实施顺序与并行边界

推荐严格按以下关键路径推进：

`P0-076 → P0-077 → P0-078 → P0-079 → P0-080 → P0-081 → P0-082 → P0-083～088 → P0-089～093 → P0-094`

可并行部分：

- P0-083、084 可在页面注册表冻结后并行。
- P0-085、086、087 可在状态机、运行时重配置和统一 action runner 接口冻结后并行。
- P0-089、090 可与对应实现同步编写，但真实 smoke 必须使用合并后的候选包。

禁止并行造成的漂移：

- 页面不得各自定义错误状态、确认流程或通知文案。
- 仓储不得由 UI 直接调用，统一经过 ConsoleApplication。
- 不得分别构建多个无法追溯到同一 commit 的测试包。

## 6. 最低可用闭环场景

以下场景全部通过前，不得宣称 V0.21 完成：

1. 全新用户打开 Console，看到项目向导而不是 `索引 ERROR`。
2. 选择小说根目录并保存后，索引自动建立并显示记录数。
3. 用户进入正文页，只看到章节；进入人物页，只看到人物。
4. 用户从人物/事件/任务详情打开相邻 Markdown 原文。
5. 用户创建当前阶段并设置焦点，先看到变更预览，确认后 Dashboard 更新。
6. 用户推进事件/游标/里程碑，看到完整影响报告，取消时零写入。
7. 用户创建一个关联事件的任务，并可在“当前任务”中看到它。
8. 制造坏缓存或单文件解析失败后，Console 显示原因并可恢复，不损坏 Markdown。
9. 重启 Obsidian 后项目、焦点、游标和索引恢复正确。
10. 实际加载包的版本、commit 和 hash 与验收报告一致。

## 7. 发布闸门

### Gate A：可进入

- 空配置不再显示技术性 ERROR。
- 项目可通过 UI 配置、切换和重建。
- 索引状态自动刷新并显示可执行的恢复动作。

### Gate B：可理解

- 全部导航路由具有正确数据范围和空态。
- 错误显示原因、影响和下一步；无静默 Promise 失败。

### Gate C：可操作且安全

- P0 写操作均有可达入口。
- 高风险写入均经过预览和明确确认。
- 并发冲突及失败补偿保持原有安全契约。

### Gate D：可发布

- 原 P0-071、P0-072、P0-075 完成。
- 候选包通过自动测试、性能测试和真实 Obsidian smoke。
- 32 条 AC 完成签字，不存在未解释的“进行中”。

## 8. 风险与控制

| 风险 | 控制措施 |
|---|---|
| 修 UI 时绕过安全写入边界 | UI 只调 ConsoleApplication；契约测试断言 ChangePlan/确认令牌 |
| 运行时重配置产生重复监听 | context 使用显式 dispose；测试监听数量和跨项目事件隔离 |
| 为兼容旧数据误写 Markdown | 导入设置和首扫保持零 Markdown 写入；legacy 默认只读 |
| 路由数量多导致重复代码 | 页面注册表、共享列表/详情/action runner，不复制业务规则 |
| 开发目录通过但发布包失败 | 候选包 hash 固化后安装验证；报告记录实际加载标识 |
| 为赶进度再次以单测替代真实验收 | P0-094 必须引用 P0-091/092 的手工证据，否则不得签字 |
